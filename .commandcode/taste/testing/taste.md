# Taste
- Wants automated tests to cover success paths as well as failure paths — explicitly asks for e.g. a test that a valid non-cash payment succeeds, not only the rejected/negative cases (also: retur tests must cover jalur sukses AND jalur gagal — stok kurang, supplier invalid). Confidence: 0.9
- Wants e2e tests added for each new feature/flow implemented (e.g., explicitly requested "tambahkan test e2e untuk alur ini" for admin CRUD produk/kategori), covering create/edit/delete plus guardrails (e.g., FK-restricted deletes rejected); the gram-products/qty-float feature likewise got its own e2e section (validation of mandatory harga_per_gram, getHargaEfektif, float qty persisted to DB). Confidence: 0.9
- Expects the e2e test suite to be re-run after every code change and wants failing assertions updated to match the new behavior rather than left red — explicitly asked "Jalankan test e2e lagi setelah ini"; later confirmed: if an assertion fails because of an intentional behavior change (e.g., timezone or struk format), fix the test to match the new behavior, then commit. Confidence: 0.9
- Wants e2e tests for CRUD flows to cover the full matrix — success (add success), validation failures (duplicate username rejected), edit, and FK-guarded delete both ways (delete without transactions succeeds; delete with existing transactions rejected). Confidence: 0.7
- Export-format tests must assert the actual file format, not just that a method runs — when export was reworked, the e2e updated to check `str_starts_with($pdf, '%PDF')` for the PDF export and CSV header content for `keCsv()`, proving each format is genuine; a method named after one format that silently returns another gets caught this way. Confidence: 0.65
- The e2e suite truncates all tables (including `users`) at the start of a run, which wipes demo accounts and breaks login afterwards — this failure recurred repeatedly (user reported "akun kasir dan admin ga bisa lagi", then it reappeared mid-navbar-work when a fresh e2e run emptied `users` again), so the suite was permanently fixed to auto-run `database/seed.php` at the end (after cleanup) and restore demo data; demo accounts must always be present and usable after any test run. Confidence: 0.95
- Wants e2e tests to verify architectural/pattern requirements explicitly, not just behavior — added a dedicated "Strategy Pattern pembayaran" test section asserting polymorphism (each strategy's `prosesBayar` rules), polymorphic change calculation, DI via setter, and that a transaction without an injected strategy is rejected with a clear error. Confidence: 0.8
- Extends the pattern-verification test habit to each new OOP requirement: for the inheritance refactor, added e2e asserts for `getHakAkses()` overrides (admin has kelola_diskon/retur; kasir lacks them), and polymorphic login returns a concrete `Admin`/`Kasir` instance per DB role (plus wrong-password → null); for the DataReporter architecture, added a dedicated e2e section asserting `instanceof DataReporter` on every implementing model — the original three plus Supplier when it was added — with output-shape asserts for `getAgregasiGrafik()`/`getDataTabel()`, search filtering, controller output, and `api.php` returning valid JSON. Confidence: 0.95
- When an e2e test must exercise a script that calls `exit`/`header()` (e.g., the front-controller `public/api.php`), invoke it via a `php -r` subprocess with mocked `$_SESSION`/`$_GET` rather than `require`-ing it inline — the inline include's `exit` terminates the whole suite mid-run and header/session warnings pollute the JSON output. Confidence: 0.8
- e2e assertions about state must compare against freshly re-fetched DB values (e.g., `Produk::cari()` again after a transaction), not stale in-memory objects from before — when the atomic-stock rework made `batalkan()` restore stock via SQL (`UPDATE stok = stok + qty`) instead of writing back a stale object's old value, the old test comparing against a stale object was fixed to re-fetch the DB value both before and after. Confidence: 0.8
- The QA/debug phase got its own e2e section covering the fixed bugs, not just new features: discount applied exactly once even when `hitungTotal()` is called twice, tax-inclusive total and payment validation, member points restored on cancel, historical HPP snapshot in `item_transaksi`, and duplicate-product merging in pembelian — bug fixes get regression tests just like features do. Confidence: 0.8
- When debugging a suspected systemic defect (one bug pattern repeated across many model files, e.g., the reused `:cari` placeholder breaking all server-side searches), verifies the hypothesis first by running a single multi-model loop (a `php -r` snippet iterating `[label, fn() => (new Model)->getDataTabel(...)]` pairs) that exercises every affected model and prints per-model PASS/ERROR — then applies the identical targeted fix to each file and re-runs the loop to confirm all flip to OK before the e2e pass. Confidence: 0.8
- Security fixes are verified at the HTTP layer with curl (not only via model-level e2e): POST without CSRF token must return 419, POST with the session's token must succeed (302/200); after adding CSRF + rate-limiting, the full login flow was re-tested end-to-end (GET page → extract meta `csrf-token` → POST with token + cookie jar → follow redirect → dashboard 200) and session cookie hardening (`HttpOnly; SameSite=Lax`) was confirmed from `Set-Cookie`. Confidence: 0.7
- Every feature improvement gets its e2e coverage extended to match the new business rules — when retur was changed to require purchase history, tests were reworked to cover the new success path (pembelian_id recorded) and the new failure paths (no purchase history, wrong supplier origin, insufficient stock); member improvements added asserts for auto-generated numbers, login via number or phone, wrong-password rejection, and point redemption success + insufficient-points + unknown-reward rejection. Confidence: 0.8
- When a new table is added to the schema, it must be included in EVERY truncate/cleanup list — the `katalog_penukaran` table had to be appended to both the seed.php truncate list and both truncate blocks in e2e.php (start cleanup and end-of-run cleanup); missing one leaves stale rows that break later assertions. Confidence: 0.7
- A page that renders blank white in a real browser while curl shows 200 + full HTML and vendor CSS/JS all load is invisible to curl/e2e checks — diagnose client-side rendering with real browser automation (agent-browser: open page, screenshot, interpret via vision, and `eval` DOM queries for classList/d-none, getBoundingClientRect, computed display) to find hidden elements (e.g., the whole `.kiosk-kiri` content column carrying `d-none` when a shift wasn't open); a green e2e suite (207/207) does not prove a page renders visually. Confidence: 0.8
- When verifying a form-driven AJAX flow with agent-browser, synthetic `click`/`fill` via element refs is unreliable on the POS page — clicks may not fire the submit handler (no POST, no state change) nor open a Bootstrap modal (`data-bs-toggle` leaves the modal closed), and `fill` can land in the wrong input (a value meant for the payment field went into the barcode field) — drive the real flow with `form.requestSubmit()` (or dispatch the submit event) and set values via `eval` targeting element IDs, then assert the resulting DOM state (e.g., `.kiosk-kanan` losing `d-none` after buka kas, `#flash-pesan` showing success) instead of concluding the fix is broken from a click-only test; to open a Bootstrap modal in this environment use `bootstrap.Modal.getOrCreateInstance(modal).show(btn)` passing the button as relatedTarget so `show.bs.modal` handlers populate hidden inputs, then assert `classList.contains('show')` and the hidden field's value. Confidence: 0.75
- Backend-only e2e has blind spots for display/state bugs (e.g., white screen or hidden right panel when no cash shift is open) — wants a documented manual test checklist for critical POS states (belum buka kas / sudah buka kas / tutup kas / ganti akun) that must be run every time transaksi.php changes; explicitly rejected adopting a full browser-testing framework (Playwright) as out of scope for a college project, preferring lightweight pragmatic verification (documented checklist + real-browser spot checks). Confidence: 0.8
- When a bug is JS/UI-only and can't be exercised by the backend-only e2e suite (e.g., submit button not disabled during AJAX), still add an e2e regression test that locks the server-side guarantee protecting the same flow — invoke the payment action twice in one shared session and assert the second call is rejected ("Keranjang masih kosong") and stock is only decremented once — and deliver short manual browser test steps for the visual behavior. Confidence: 0.8
- For subprocess tests that must share one PHP session across multiple invocations and set superglobals (e.g., simulating a second 'bayar' tap on transaksi.php), use a dedicated helper script under test/ (test/double_tap_helper.php) invoked as `php test/...` instead of a long `php -r` one-liner — Windows escaping mangles `$_SERVER`/`$_POST` assignments in long inline commands, while a helper file is reliable; PHP session ids must also stay in the legal charset `[A-Za-z0-9,-]` (underscores break session_start with 'illegal characters'). Confidence: 0.7
- Wants responsive/mobile layout verified in a real browser at representative viewports (mobile ~375×812, tablet ~834×1112), not just desktop — screenshots interpreted via vision to catch clipped/overflowing controls (e.g., a "Kamera" button cut off at the screen edge), then fixed with responsive CSS (media-query wrap/stack) and re-verified before e2e. Confidence: 0.5
- Verifies responsive layout across a breakpoint gauntlet in a real browser (narrow phone 320px, ordinary phone, tablet 768px, laptop 1024px), programmatically asserting `document.documentElement.scrollWidth <= clientWidth` (no horizontal scroll) and that every focusable text input/select/textarea has computed font-size ≥16px at mobile widths — then fixes found overflow (e.g., a `text-nowrap` toolbar button still clipping at 320px by switching the toolbar form to a full-width `flex-direction: column` at <576px) and re-screenshots to confirm. Confidence: 0.6
- Verifies JavaScript syntax with `node --check <file>` before running the e2e suite whenever a `.js` file is edited (e.g., `node --check public/assets/pos.js`), the JS analogue of the `php -l` pre-commit check. Confidence: 0.7
- Creates temporary QA test scripts (e.g., `test_wa_tmp.php`, `test_wa_retry_tmp.php`, mock server/log files) for feature-specific smoke and failure/retry testing, then cleans them up (`rm -f` + kill mock servers) afterward to keep the working directory free of QA artifacts. Confidence: 0.8
